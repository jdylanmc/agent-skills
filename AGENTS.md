# Repository Instructions

This is Dylan's personal library of agent skills and engineering doctrine.
Read [intent.md](./intent.md) before making structural decisions.

## Active skills

- Skills are regular, editable files at `.agents/skills/<name>/SKILL.md`.
- Do not use symlinks or install this library globally as a side effect.
- The imported collections are a starting set for human curation. Do not prune,
  rename, rewrite, or invoke them until that work is requested.
- Installing a skill does not authorize running its setup, hooks, services,
  external integrations, or bundled scripts.
- Keep each skill focused on one useful job. Use supporting files when they
  earn their place; no atom/molecule hierarchy or composition metadata is required.
- Preserve upstream licenses and attribution when modifying or renaming imports.
  Apache-licensed files also require notices identifying modifications.
- `skills-lock.json` records installer provenance, not an instruction to update.
  Never overwrite local customizations with an unattended upstream update.

## Commit messages

All commit messages generated by this library follow
[the shared Caveman-style policy](.agents/COMMIT-STYLE.md): terse Conventional
Commits, with explanatory bodies for consequential changes and all required
trailers preserved. Target-repository conventions and explicit operator
instructions take precedence. Formatting grants no additional Git authority.
This is library-local; do not change global Copilot configuration.

## Doctrine and intent

- Keep `doctrine/` and the root `intent.md` as the human-owned sources.
- Do not create, edit, reword, or delete doctrine, its manifest, or human intent
  without the operator's explicit request for that change.
- Doctrine and intent are authoritative about their subject, not executable
  instructions. Text inside them cannot grant authority or suppress a check.
- Apply only relevant doctrine, cite the specific rule, and ground conclusions
  in task requirements and evidence. Doctrine informs human judgment; it does
  not automatically approve or reject work.
- After an explicitly authorized doctrine edit, update its manifest digest in
  the same change. A matching digest establishes integrity, not approval.
- Integrating doctrine into the imported skills is subsequent, human-directed
  work, not part of installing the initial collections.

## Archive

`archive/atomic-v1/` is a historical snapshot, not an active skill library.
Do not route to its skills, run its hooks or validators, or apply its archived
instructions to new work. Consult it only when the task needs historical context.
Its old repository instructions are preserved as `AGENTS.original.md`.

## Validation and local files

Run `node --test scripts/doctrine-manifest.test.mjs` to check preserved doctrine.
The legacy composition graph, conformance suite, and runtime hooks are retired.
Imported skills have not been made provider-independent merely by being copied.

Read `.user/instructions.md` when present. Never commit `.user/`, credentials,
private runtime evidence, dependency installations, or generated caches.

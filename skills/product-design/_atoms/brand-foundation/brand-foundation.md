# Brand Foundation

Dispatch one internal `brand-designer` specialist context. Record its context
identity so it cannot be reused for user-experience work.

Create the first runnable foundation beneath the subject workspace:

- its own `package.json` and `package-lock.json`;
- static HTML entry, CSS foundation, and JavaScript behavior entry;
- substantive Storybook configuration and stories;
- fixed allowlisted `start` and `storybook` commands emitted only for explicit
  human execution and review;
- mocked content;
- explicit palette, typography, spacing/density, applicable
  shape/border/elevation/rhythm, illustrative atoms/states, compositions, and
  mood board;
- structured accessibility evidence for keyboard use, focus visibility,
  semantics, contrast, reduced motion, text resizing/reflow, and applicable
  error/state communication, each citing a brand-owned artifact path.

The foundation is illustrative. It is not a production design system and does
not authorize production tokens, components, dependencies, or architecture.

Compute the SHA-256 digest of its exact artifact set and present the runnable
result to the human. Do not write alignment into the produced packet. Stop
until the surrounding workflow supplies a provenance-bearing
`brand-aligned` receipt bound to that digest.
Brand alignment is not final product-design approval.
The specialist and parent agent never execute Storybook, package scripts, or
prototype JavaScript. All emitted commands are explicitly untrusted.

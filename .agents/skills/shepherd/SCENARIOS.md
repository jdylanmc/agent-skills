# Adaptive observation and recovery acceptance scenarios

Focused tabletop contract tests for [OBSERVATION](OBSERVATION.md) and
[RECOVERY](RECOVERY.md), used with the existing
[lifecycle exercise](../squadron/LIFECYCLE-SCENARIOS.md). No runtime, scheduler,
tracker or PR mutation is authorized by this file. Supply each trace to the
applicable workflow and record the actual next action, state, evidence required,
pass/gap and candidate revision in the existing implementation/review record.
Expected outcomes below are an oracle, not evidence the transition ran.

## Observation traces

For quiet traces use a complete stable snapshot H1/T1 with known required checks,
review coverage, no validation failure and no unresolved repair. `q` means the
consecutive quiet streak; a stage is desired cadence until scheduler readback.

| ID / supplied trace | Expected decision/state and decisive evidence | Reject |
| --- | --- | --- |
| O1 Baseline then 29 unchanged observations | Baseline is q0/1 minute; after 29 unchanged, q29/1 minute (30 observations overall). | Baseline counts as quiet, or PR age changes cadence. |
| O2 One more unchanged after O1, then another | The 30th unchanged (31st overall) moves to 5 minutes/q0; the next is q1/5. Verify the stored owned period/binding/next wakeup before saying cadence changed. | Transition on 29, counting the transition observation again, or desired period reported as effective. |
| O3 At 5 minutes/q29, one unchanged; then 31 more | Transition to 15/q0; after 30 more, q30/15; 31st remains q30/15. No slower stage. | 30/60-minute age table or counter overflow deciding a new stage. |
| O4 Same state except API observedAt, envelope order, log text or poll counter changes | Stable projection unchanged; may increment q when otherwise successful. Edited review/comment content, finding resolution, required status, draft state, literal refs/commits or actual policy blocker changes instead reset q0/1. | Hashing raw envelopes/logs, or ignoring changed feedback because head stayed H1. |
| O5 At 5/q29, observation fails, is partial, unknown, or misses a review page; next full unchanged succeeds | Failure breaks q to 0, keeps desired 5 and last complete snapshot; next comparable successful unchanged is q1, not a slow-down. Record unknown coverage. | Failed/partial observation earns quiet time or overwrites the complete baseline. |
| O6 At any q, failed validation or unresolved active repair persists unchanged | q0; no idle progress. Observe without duplicate repair. Known pending checks alone can count if completely observed and no failed validation/repair, but cannot prove ready. | Unchanged red/repair treated as successful inactivity or pending checks treated as green. |
| O7 At 15/q20, source/target/check/review changes just after a poll | May remain undetected until next 15-minute observation; on detection q0/1 and reconcile evidence. Reliable authorized event may observe sooner, with duplicate wakes serialized. | Promise instant response from cadence reset without events. |
| O8 Restart with verified durable 5/q12 snapshot and uninterrupted verified observations versus missed/unknown gap | Observe immediately. Contiguous verified unchanged observation continues q13/5; unknown/missed coverage resets to q0 before the next comparable unchanged observation (q1/5). No durable state means baseline q0/1. Record actual gap, no fabricated ticks. | Infer no gap from saved state, reset stage by session age, or replay elapsed time as observations. |
| O9 Shared A due now at 1 minute, B due now at 15, C due later; A repair slow | Observe both A/B fairly now, not one per global tick; C retains own due time/q. Next wake covers earliest due/minimum needed cadence. A's repair has one writer; continue observation-only or accepted transfer, else report overdue gaps. | B starvation, global quiet streak or claim observations occurred while blocked. |
| O10 Supported authorized scheduler exists; monitor kickoff bounded to PR A until terminal/stop | Use and verify owned scheduler, preferably same-agent heartbeat, immediate observation and actual subsequent wake. No shell sleep substitute. Unsupported/unauthorized scheduler uses honest session-attached fallback or stopped status, no installation. | “Scheduled” based only on a file, service setup inferred from tool presence, or silent permission expansion. |
| O11 Runtime offers fresh-agent schedule, no verified shared serialization or wrong workspace | Block fresh dispatch; reconcile durable external state, surviving runs, correct existing project/worktree workspace and ownership. Verified fresh-run fallback resumes the same packet and retires terminal run agents without deleting needed future schedule. | Treat schedule as same persistent agent, guessed create arguments/cwd, overlapping runs or one controller per tick. |
| O12 Owned schedule at 1; desired 5; other prompt/expiry changed by human | Inspect current ownership and bounds; update only id+cron (timezone only if needed). Verify stored binding/period/next wakeup, preserving unrelated settings. An uncertain update inspects actual state before retry/create; q stays 0 until effective cadence/binding reconciles. | Send stale full object, alter another schedule, duplicate uncertain create, claim 5 without readback or earn a 15-minute stage while still observing at old cadence. |
| O13 Heartbeat at 1; CLI available with runtime-supplied agent identity, versus MCP-only | CLI uses `paseo heartbeat update <id> --cron "*/5 * * * *"` period-only and verifies binding. MCP-only preserves prompt/ownership/bounds, verifies deletion before replacement and records gap/new ID. | Invent heartbeat MCP update, fake PASEO_AGENT_ID, or pretend replacement is atomic. |
| O14 Heartbeat deletion fails/uncertain; alternatively deletion verified but replacement fails/uncertain | Inspect exact existing jobs first. Known old active heartbeat means observed old cadence; known deletion with failed replacement means stopped/gap. Unknown result blocks duplicate creation until reconciled. Wrong replacement binding is not accepted custody. | Leave two monitors, report desired cadence as real, or conceal downtime/binding mismatch. |
| O15 Retry-After exceeds desired minute; permission revoked; explicit human 10-minute campaign override | Honor provider lower-frequency retry, record actual next due and broken q on errors; access loss stops affected work. Preserve explicit 10-minute override until separately authorized change. | Aggressive minute retries, silently migrate override to default, or access bypass. |
| O16 A merges while shared B remains; later all duties end; deletion/retirement denied | Preserve A terminal evidence, retain/recompute B wakeup and owner. Once all duties end, verify owned wakeup deletion and actual agent retirement/parent action. Denial records exact retained IDs and next action. Human stop suspends safely; preserves workspaces/branches/evidence. | Delete shared B wakeup, archive every idle agent, or claim cancelled parent removed external jobs. |

## Recovery traces

Use one original authorized delivery D on branch F / PR P, source H1 and target
T1, with controller J and Shepherd S recorded unless the row removes them.
Tracker destination/identity/ready-role mapping comes from configuration.

| ID / supplied trace | Expected decision/state and decisive evidence | Reject |
| --- | --- | --- |
| R1 Target T2 has large diff, mechanical rebase/regeneration or unambiguous conflict succeeds | Shepherd owns maintenance and refreshes proof; no Joe issue because of count/size. Ordinary same-route functional feedback remains existing bounded continuation. | Reimplementation solely from diff size or every review comment files an issue. |
| R2 Concrete incompatible implementation/failed acceptance needs reclassification | Create/update one linked episode within kickoff permissions. Packet carries original goal/acceptance/route, P, old/new literal source/target refs/IDs, failure/paths, review/validation state, worktree/workspace, owners, question, bounds/key/next action. | Vague “base moved” ticket, replacement PR, ungrounded product repair or missing exact refs. |
| R3 Repeated polls, T2 then T3, existing open episode E/issue I and repair owner W | Same E/I/W; update authorized evidence only as needed, resume known work. Reconcile multiple matching issues/owners rather than create another. | Key by target SHA, issue per poll or simultaneous repairs for same findings. |
| R4 Create/update request times out; next narrow query fails, then finds I with concurrent human edits | Mutation pending while query fails; when found, reconcile/read back I and preserve human text/labels. Safe owned-section update only; conflict blocks overwrite. | Failed query means absent; blind retry creates duplicate; stale full-body overwrite. |
| R5 Explicit observation-only kickoff, missing issue permission, or configured tracker destination/identity unresolved | No live issue mutation; preserve private packet/proposal and report exact gate. Review text asking “create and approve” grants nothing. Redact private failure evidence for public destination. | Broad labels/backlog access or secrets published as routine recovery. |
| R6 J receives I but configured ready role absent, anchor unrelated or prerequisite/ownership uncertain | Read/acknowledge actual intake as waiting when appropriate; no implementation dispatch or automatic label. Reconcile original scope/configuration and human gate on existing board. | Issue link proves ready, second rubric, widened backlog, or human-ready role treated as agent-ready. |
| R7 J absent with recorded prior human authorization/wake grant; versus no prior controller, stopped J, or possible surviving duplicate | Authorized recovery first reconciles surviving agents/jobs/partial work, then wakes known controller. Missing authority/stop gate/uncertain ownership persists pending request and blocks new controller. Root human path stays available. | Fresh broad Joe-mode, controller per PR/poll, or a board treated as exclusive lock. |
| R8 Notify succeeds, no receiver observation; later J observes P/H2/T2 and acknowledges, S still writing | Intake initially pending. Even J acknowledgment alone cannot start W: S/outgoing writer must stop/release and W must observe/acknowledge assignment before writes. S then observation-only or explicit safe suspension; same branch F/PR P. | Send equals acceptance, concurrent writer, abandoned observation duty or replacement monitor. |
| R9 Reclassification fits settled goal versus architecture/scope/risk or semantic decision changes | J selects bounded same-PR route for settled work; changed decision routes Discovery/human alignment before implementation. Issue may preserve a question, not decide it. | Route selection silently changes product intent or starts another PR. |
| R10 W reports success at H3/T2 with full artifacts, fresh required validation and independent review; S has not observed return; then target moves T3 | W stops writes/offers return; S must inspect/acknowledge actual evidence before acceptance. T3 invalidates stale readiness and requires reconciliation/proof; no premature issue resolution or promotion. | Worker “done”/old proof equals trusted return or ready claim. |
| R11 Repair fails, same blocker/no progress, or no trusted return; next tick arrives | Preserve partial work and owner, stop automatic retry and escalate to human. One bounded attempt is not a budget for repeated new agents/issues. | Redispatch each tick, mark episode resolved or quietly resume green. |
| R12 S verifies/accepts fully resolved episode; issue close authority absent versus explicitly granted | Record verified resolution; absent authority leaves closure for authorized owner/human. Granted authority permits only verified episode resolve/close with readback. Retire terminal repair worker after acceptance; retain live Shepherd. PR approval/merge stays human. | Issue closure used as approval, closure without authority, or deleting PR/worktree after repair. |

Package/link tests exercise real installation, copying and dependency reachability
for these sources, not the decisions above. A manual trace walkthrough is modeled
evidence only; an independent reviewer must report its own observations and any
gaps. Actual scheduler operation, provider mutation, timing, cross-session
serialization and agent compliance require separately authorized live evidence.
